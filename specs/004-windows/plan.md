# Plan 004: LangSwitch для Windows

## Как строим
- **Язык:** C# на **.NET Framework 4.8**. Он уже встроен в Windows 10 и 11, так что ничего доустанавливать не нужно. Получается один файл `LangSwitch.exe` весом примерно 3–4 МБ, вместе со словарями.
- **Окна:** WinForms: значок в трее (`NotifyIcon`) и окно настроек с вкладками (`TabControl`).
- **Ловим клавиши:** системные перехватчики клавиатуры и мыши (`WH_KEYBOARD_LL`, `WH_MOUSE_LL`). На Windows для этого не нужно разрешение, как «Универсальный доступ» на Mac.
- **Двойной Shift:** та же логика, что в `KeyMonitor.swift`: нажал, отпустил, снова нажал и отпустил, ничего другого между нажатиями.
- **Буквы слова:** `ToUnicodeEx` с раскладкой активного окна. Флаг `0x4` не портит состояние клавиатуры.
- **Смена языка:** `WM_INPUTLANGCHANGEREQUEST` активному окну. Раскладки берём из `GetKeyboardLayoutList`, ищем русскую (0x19) и английскую (0x09).
- **Печать и стирание:** `SendInput`: Backspace × N, потом буквы через `KEYEVENTF_UNICODE`. Свои нажатия помечаем меткой в `dwExtraInfo` и сами на них не реагируем.
- **Словари:** вместо системного словаря macOS берём частотные словари RU и EN (FrequencyWords, лицензия CC BY-SA 4.0) и вшиваем их в exe в сжатом виде. В каждом примерно 200 тысяч слов. Хранение компактное: одна отсортированная строка и поиск делением пополам, около 10 МБ памяти.
  - Решение «исправлять или нет» делаем по частоте: исправляем, если в другой раскладке слово встречается минимум в 20 раз чаще. Так «lf» (мусор в английском) → «да», а «ok» и «hi» остаются как есть.
- **Выделенный текст:** читаем через UI Automation (аналог Accessibility на Mac). Если выделение прочиталось, кладём исправленный текст в буфер, жмём Ctrl+V и возвращаем буфер как был. Если не прочиталось, просто меняем язык. Ctrl+C «вслепую» не используем: VS Code и некоторые другие программы без выделения копируют целую строку.
- **Поле пароля:** UI Automation `IsPassword` у элемента в фокусе. Проверяем только перед заменой, не на каждую клавишу.
- **Тяжёлая работа** (UI Automation, буфер обмена, печать) идёт в отдельном потоке. Перехватчик клавиш остаётся мгновенным, иначе Windows его отключает.
- **Настройки:** `%APPDATA%\LangSwitch\settings.ini`. **Автозапуск:** `HKCU\...\Run`, права администратора не нужны.
- **Один экземпляр:** Mutex. При повторном запуске первая копия открывает настройки.

## Структура
```
windows/
  LangSwitch.csproj        — проект (net48, один exe)
  src/Program.cs           — запуск, один экземпляр
  src/TrayApp.cs           — значок в трее, меню, логика двойного Shift (как AppDelegate.swift)
  src/KeyMonitor.cs        — перехват клавиш/мыши, двойной Shift, текущее слово
  src/InputSwitcher.cs     — раскладки RU/EN
  src/LayoutConverter.cs   — ЙЦУКЕН ↔ QWERTY (копия логики с Mac)
  src/Dictionary.cs        — частотные словари
  src/Corrector.cs         — решает, что исправить (раскладка, регистр, опечатки)
  src/TextFixer.cs         — стереть/напечатать, выделение, буфер обмена
  src/Native.cs            — вызовы WinAPI
  src/Settings.cs          — настройки + автозапуск
  src/SettingsForm.cs      — окно настроек
  res/words-ru.txt.gz, res/words-en.txt.gz, res/app.ico
install.ps1                — установка одной строкой
```

## Сборка
GitHub Actions: в `ci/release.yml` добавляем вторую задачу на `windows-latest` (`dotnet build -c Release`). Она кладёт `LangSwitch-windows.zip` в тот же релиз, что и Mac. Версию exe берём из тега.

`install.ps1`: скачивает zip → `%LOCALAPPDATA%\Programs\LangSwitch` → ярлык в «Пуск» → автозапуск → запуск. Без прав администратора. Если файл скачан через PowerShell, SmartScreen не ругается.

## Проверка по constitution
- Лёгкость ✅: живёт в трее, ~25 МБ памяти. Это больше, чем на Mac, потому что словари свои. Цель < 40 МБ.
- Без лишних зависимостей ✅: только .NET Framework и WinAPI, которые уже есть в Windows. NuGet нужен только при сборке (справочные сборки).
- Приватность ✅: в памяти только текущее слово, на диск пишем только настройки.
- Не ломать ввод ✅: пароли пропускаем, при сомнении ничего не делаем, выделение без UI Automation не трогаем.
- Проверка на живой Windows: Павел проверяет на своём компьютере.
- Отступление: принцип 2 говорит про Swift и macOS. Для Windows-версии стек свой (C#), но принцип «только системные библиотеки» сохраняем.

## Риски
- Неподписанный exe с перехватом клавиатуры может вызвать подозрение у антивируса. Код открыт, ничего не отправляет. Если начнутся ложные срабатывания, подумаем о подписи.
- В программах, запущенных от администратора, Windows не даёт печатать. Там работает только смена языка.
